# 踩坑与失败方案（PITFALLS.md）

本文档记录本汉化项目中失败的做法、误导性假设、脆弱流程与兼容陷阱。目的是保存**负面知识**。

条目按模板记录；失败方案不因最终采用别的方法而删除。

---

## 1. 字符表 index ≥ 1280 出现"粉色 @"（扩格未改 exe）

**状态：** 已验证
**影响范围：** 字体 / 资源格式
**症状：** 把字符表 index 1280–1407 的空位改成简体字后，原本显示 `?` 的字变成**粉色 `@`**，无一个字变汉字。
**初始假设：** 只要图集有空位、字符表有空槽即可扩格。
**实际原因：** exe 建表循环 `cmp edi,0x13FC` 硬跑 **1280 次**，二分查找上限常量 `0x4FF(=1279)`；
坐标表只有 1280 项。index ≥ 1280 能被字符表命中，但坐标表未初始化 -> 垃圾坐标 -> 粉 `@`。
**失败做法：** v2.6 只改图集与字符表、不改 exe。
**正确解法：** 必须改 exe（见 v2.8 起）。
**如何检测：** 装机后看是否有粉 `@`；`ascii_reserved()`/坐标表项数核对。
**回归测试：** 覆盖率统计 + 进游戏抽检。
**相关文件：** `build_cn.py`（`UNLOCK_1280` 注释块）、`历史报告（未入库）：汉化补丁v2.6-扩字格实验说明.md`。

## 2. 扩容到 4096 后"启动即闪退"（循环上限差 1）

**状态：** 已验证
**影响范围：** 可执行补丁 / 字体
**症状：** v2.11（2048×2048 图集）、v2.12（1024×1024 图集）改装后**游戏启动即闪退**。
**初始假设：** 图集尺寸超限（引擎单边上限 1024~2047）导致闪退。
**实际原因：** 建表循环上限写成了 `N*4`。该循环为 `cmp edi,L; jl`（`edi=4i-4`），
迭代次数 = `L/4 + 1`，**正确值必须是 `4N-4`**（原版 1280 用的正是 `0x13FC=4*1280-4`）。
写 `N*4` 会多跑一轮 `i=N`，把排序表指针写到 `.atbl` 节末尾之外 -> 越界写 -> 访问违例 -> 闪退。
**失败做法：** v2.11/v2.12 反复改图集尺寸，均未命中真因。
**正确解法：** v2.13 把循环上限改为 `4N-4`；并用逐位证明确认 4096 索引与图集格双射不重叠。
**如何检测：** 启动即崩；反汇编循环边界。
**回归测试：** 启动 -> 进菜单 -> 进关卡；`design`/verify 脚本核对索引唯一性。
**相关文件：** `build_cn.py: patch_exe_unlock()`、`历史报告（未入库）：汉化补丁v2.11/2.12/2.13*.md`。

## 3. 跨图集搬迁导致省略号"蓝绿描边"

**状态：** 已验证
**影响范围：** 字体
**症状：** 扩格后省略号 `…` 等符号出现蓝绿色描边。
**实际原因：** v2.13 的取格公式把 index 1024–1279 从图集 A 换到了图集 B，
而两页调色板不同（A 的 idx19/20 = 灰，B 的同名 idx = 青绿）-> 串色。
**正确解法：** v2.14 换一套取格公式（`shr ecx,11` / `V&63` / 页号 `62+bit10`），
让**原版字形一格不跨图集**，跨图集搬迁数 = 0。
**如何检测：** 观感比对；调色板索引核对。
**相关文件：** `build_cn.py`（`game_cell()`/`old_cell()`/`LAYER`）、`历史报告（未入库）：汉化补丁v2.14*.md`。

## 4. 定长槽"多写几字节"清零相邻 int 字段 -> 选关/选章闪退

**状态：** 已验证
**影响范围：** 资源格式 / 补丁
**症状：** 选章节/选关进入时闪退。
**实际原因：** 两次同型事故——
- v2.59：章节名槽写 68 字节，真实容量 64，多写的 0 清掉 `pos68` 的**世界/章节组编号**（73/85 条非零）；
- v2.61：村落表地名槽固定写 40 字节，真实容量 32（184 条），多写的 0 清掉 `off136` 的**关卡/幕编号**（64 条）与 `off140`（49 条）。

游戏按这些编号索引资源，得 0 -> 越界 -> 闪退。
**正确解法：** 容量取**保守最小值**（章节 64 / 地名 32）；写入只覆盖到字段边界，
并加"写后越界守卫"（把紧随其后的 4 字节按原样回填）；体检新增 `cscv[28] off136/off140` 检查。
**如何检测：** 写后 diff 审计（差异须全落在登记槽内）+ 体检。
**回归测试：** 选章/进入关卡不闪退。
**相关文件：** `build_cn.py: CSCV_CHAP_JOBS / apply_cscv_place() / CSCV_PLACE_LEN`、
`历史报告（未入库）：闪退修复报告-v2.61-20260917.md`。

## 5. cscv "内容匹配同步"误伤脚本层键名 -> 机制断链

**状态：** 已验证
**影响范围：** 资源格式 / 补丁
**症状：** 同伴不能攻击/用技能（v2.28）；选关"勇者城"消失（v2.64）。
**实际原因：** `cscv.s2a` 中有一批与 `LANG_JA` **逐字节相同**的 blob；它们其实是**脚本/数据层**，
游戏按 CP932 原码做按名比对。构建的"内容匹配同步"把 LANG 侧译文（载体码）写进了这些孪生 blob，
字符串彻底改变 -> 按名比对失败 -> 机制断链。
**失败做法：** v2.28 把 cscv 与 LANG 一起改。
**正确解法：** 同步时**跳过键名类槽位**（`cscv_skip_keys`，判据 = 原文 ∈ collide）；
对内容匹配配不上的孪生表**显式按 cscv 索引写入**（`CSCV_CHAP_JOBS`），并只写显示字段。
**如何检测：** cscv md5 写前写后断言；cscv 孪生名字键字段断言为日文原版。
**相关文件：** `build_cn.py`（v2.64 `cscv_skip_keys`、`CSCV_CHAP_JOBS`）、`tools/fix_954.py`。

## 6. 技能表"键名列"被一起翻译 -> 主角技能全放不出来（G5 事故）

**状态：** 已验证
**影响范围：** 补丁 / 翻译
**症状：** G5 首批装机后，主角技能全部放不出（仅 `急所突き` 幸免，因其键名是假名）。
**实际原因：** 技能表 `b666`（stride 376）的 `pos292` 是**内部键名**（脚本执行时按名查技能）；
G5 为与官方 EN 一致把 `pos292` 也翻了 -> 键名改变 -> 查不到 -> 技能无效。
**正确解法：** G5b 排除键名列（`EXCLUDE_POS=[(666,288,400)]`），只翻 `pos0` 显示名
（且须与武器表 `pos168/204/236` 的副本同改）；体检新增"键名列须日文原版"守卫。
**教训：** 动任何名字表前，**先做"键名列排查"**（先找出表里哪些列是键）。
**相关文件：** `build_cn.py: MECHANIC_BLOBS`、`历史报告（未入库）：G5技能名-报告.md`、`t192_skill_fields.py`。

## 7. "露露菲"名字实验失败：名字保留原文定局

**状态：** 已验证
**影响范围：** 翻译 / 机制
**症状：** 把同伴"露露菲"的全部名字副本（310 处）改成中文后，**她的攻击失灵**。
**背景：** 此前两种翻法也失败（连配置表一起翻→崩；键表被连带翻译→同伴技能全灭）。

**注意：** 2026-09-18 起，采用"仅写 LANG + 全副本同改 + cscv 全保日文 + 账本回滚"的方法，
在实验 D/E 中出现反证（武器技恢复触发），使该结论产生张力；最终以实机实验为准。
**相关文件：** `历史报告（未入库）：回滚报告-露露菲实验失败-20260913.md`、

## 10. 载体码字频漂移 -> DLC01 文本错乱

**状态：** 已验证
**影响范围：** 构建 / 字体
**症状：** DLC 内女神像指令、NPC 对话整句乱码（如 `女神像ワープ` -> `神女像传族`）。
**实际原因：** 载体码 `cmap` 按**字频排序**分配；主译表更新（术语统一等）后字频重排、字换码，

**铁律：** 任何改译表后的重装，**所有独立装机器必须一起重编码**。
**相关文件：** `build_cn.py: refresh_dlc01()`、`历史报告（未入库）：DLC01文本错乱-根因与修复报告-20260915.md`。

## 13. `\uf8f3` 前缀导致 collide 假命中

**状态：** 已验证
**影响范围：** 翻译
**症状：** 部分普通文本被误当"专有名词"保留原文（如 MESS 表 63 条含 Dash）。
**实际原因：** 名字字段带 `FF FF FF FF` 前缀，CP932 解码为 `\uf8f3…`；
碰撞白名单中有大量 `\uf8f3` 开头的噪音串，直接比对会假命中。
**正确解法：** 比对前统一 `strip_f8f3()` 剥离前缀。
**相关文件：** `build_cn.py: strip_f8f3()`、`历史报告（未入库）：v2.22-Dash与Pray修复报告.md`。

## 20. 其它经验（简记）

- **[已验证]** `cscv == cscv.bak` **不是**不变式（主汉化重建过字库）；真正的守卫是
  "孪生名字键仍日文原版 + apply 前后 md5 不变"。
- **[已验证]** 定长表字段偏移必须**实测**，不要按猜测改（MESS：`+0` key / `+36` `FFFFFFF` / `+40` value 124B）。
- **[经验]** 已装显示日/英**不等于**漏翻（可能是 collide 保护 / 孪生没写 / 前缀假命中 / 整表未登记）。
- **[经验]** CSV 含逗号字段要加引号；容量 = `ord<0x80` 记 1 否则记 2。
- **[经验]** 改译表后重装前，`verify` 易假阳性 -> 统一用 `swap_verify.py`。

## 21. 歌词被 collide 假命中拦下，且只放行了"3 行中的 1 行"

**状态：** 已验证（2026-10-20）
**影响范围：** 翻译
**症状：** 第四章关底歌词浮层（3 行）里第 1 行已是中文，第 2/3 行仍是原文
（EN 语言显示英文、JA 语言显示日文）；`さあ今こそ` / `船出の時よ` 本是一句、

1. 这 3 行歌词原串同时出现在 cscv **独有** `blob355`（女神房间歌曲表）里
   ⇒ 命中 collide 白名单，被整段保留原文；
2. `ui_always.json` 恰好收录了第 1 行 `どんな場所でも私は歌う` ⇒ 只有它被放行，

**v2.31 的缺口：** 早期歌词方案（`SONG_OK`）只覆盖主线 LANG `blob1025` 的 3 条原串，

本轮实测：`どんな場所でも私は歌う`/`さあ今こそ`/`船出の時よ` 在 LANG_JA 仅 `blob730`（各 1 处）、

- 靠 `ui_always.json` 顺带放行个别行，会出现"半中半原"的误导性中间态；
  歌词应统一走 `SONG_OK` 专用放行清单。

**同类 bug 的推广（2026-10-20 同日）：** 同一 bug 类并非只发生在第四章关底，
而是**遍布各章节关底的歌词字幕**（14 个 stage blob，见 `TECHNICAL.md` §5.3.2）。
`SONG_OK` 原先只收了主线 `b1025` 三条原串，其余全部被 collide 拦下、显示原文。

union 判据 = "原串在 LANG_JA **全库**只落在该 stage blob 的歌词槽位（`ja_cmp` 整槽匹配），

## 22. "显示原文"不等于"受保护"：整 blob 未登记才是常见漏翻原因

**状态：** 已验证（2026-10-20）
**影响范围：** 翻译 / 构建
**症状：** 游戏里仍有原文（如 `Mermaid Clan: There are still Evil Mermaids! Help me!`、
`Offense increased!`、`Fort destroyed!`），但校对视图的 `protected/` 里找不到它们。
**初始假设：** 没翻 = 被 collide 白名单保护。
**实际原因：** `rewrite_text()` **只改写 `text_v2.csv` 里登记过的 `(blob, offset)` 槽**。
全库 1058 个 LANG blob 中有 106 个**没有任何登记行**，这些 blob 里的显示文本从未被构建器看见，
与 collide 无关。另有 37 个未登记 blob 是 **CSCV 结构**（脚本/事件表），字符串藏在记录字段里。
**正确解法：** 先按 `compute_collisions()` 的**精确判据**（串作为子串出现在 cscv 的"独有 blob"中）
判定是否真受保护；不受保护的再实测字段边界后补登记行。
**如何检测：** 扫描"未登记 且 LANG_JA≠LANG_EN 且等长"的 blob，簇化差异段后按可打印率/字符集过滤二进制噪声。
**重点提醒：**
- 差异簇里混有大量**二进制/压缩数据**（`b44/b140/b155/b238/b383/b634/b648/b664/b698/b805/b968`），
  同一字符占比 ≥45% 基本就是填充噪声，不能当文本处理。
- `b252` 这类 CSCV 结构：字段 = 记录起 `+24`，**容量取到下一条记录头之前**（实测 128 字节，
  记录头为 `08 00 00 00`）；容量按"到下一个非 NUL 字节"算会被严重低估（同 `PITFALLS.md` 中
  "propagation capacity 需 padding-aware"的教训）。
- 说话人名 `YuJa` 之类**全库 0 命中**的串是运行时/存档动态值，不是漏翻，也无法翻译。
**相关文件：** `tools/build_cn.py: rewrite_text()/compute_collisions()`、
`docs/KNOWN_ISSUES.md` §12、`locales/zh-CN/text_v2.csv` row 61239。
